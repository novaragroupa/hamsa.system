# نظام إدارة همسة للسياحة

نموذج تفاعلي (Prototype) لنظام إدارة شركة همسة للسياحة — تسجيل دخول بأدوار متعددة، ولوحات تحكم منفصلة لكل قسم (المدير، HR، العلاقات العامة إن دور/أوت دور، الاستقبال، الحسابات، الكول سنتر، التسكين، حجوزات النظام).

## الملفات

```
homsa-system/
├── index.html          # الواجهة كاملة (تعمل مباشرة في المتصفح، أو عبر GitHub Pages)
├── database/
│   └── schema.sql       # سكريبت SQL لإنشاء الجداول على Supabase (Postgres)
└── README.md
```

## حالة الربط بقاعدة البيانات

النظام متصل بـ **Supabase (PostgreSQL)** مباشرة من المتصفح عن طريق مكتبة `supabase-js` — كل البيانات بتتقرأ وتتحفظ فعليًا في قاعدة بيانات حقيقية، مش تخزين مؤقت.

### إعداد Supabase (5 دقايق)

1. اعمل حساب / سجّل دخول على [supabase.com](https://supabase.com) واعمل **مشروع جديد** (Project).
2. من القائمة الجانبية افتح **SQL Editor** → **New query**، والصق محتوى الملف `database/schema.sql` كامل، واضغط **Run**.
   - ده هيعمل كل الجداول المطلوبة تلقائيًا، ويزرع فيها الحسابات التجريبية التسعة في جدول `users`.
3. من **Project Settings > API** خُد:
   - **Project URL**
   - **anon public key**
4. افتح `index.html` ودور على السطرين دول (تحت تعليق "Supabase (Postgres) backend")، واستبدلهم بالقيم بتاعتك:
   ```js
   const SUPABASE_URL = "https://YOUR-PROJECT-REF.supabase.co";
   const SUPABASE_ANON_KEY = "YOUR-ANON-PUBLIC-KEY";
   ```
5. احفظ وارفع التعديل. لو الرابط والمفتاح مش متظبطين، النظام هيشتغل تلقائيًا بتخزين مؤقت محلي (تجربة فقط، البيانات مش بتفضل محفوظة بين الجلسات) — ده مفيد للتجربة السريعة قبل عمل Deploy.

### تشغيل الواجهة

- افتح `index.html` مباشرة في أي متصفح، أو
- فعّل GitHub Pages للريبو (Settings → Pages → اختر branch: main، Folder: /root) وهيديك رابط تقدر تفتح منه النظام من أي مكان.

## الميزات الجديدة: الفرق وتحليل البيانات

- **الفرق (Teams)**: قسم جديد "الفرق" (متاح لـ admin و hr) لإنشاء فرق داخل أي قسم، وتحديد **قائد الفريق (Team Leader)** من الموظفين. كل موظف في شاشة "الموظفون" بقى ليه حقل "الفريق" يربطه بالفريق بتاعه.
- **تحليل البيانات (Analytics)**: قسم جديد "📊 تحليل البيانات" متاح لكل الأقسام (مش بس العلاقات العامة زي المثال المرفق)، وبيسمح لكل قسم إنه:
  1. يعمل **لوحة (Board)** جديدة مرتبطة بمصدر بيانات القسم بتاعه (الشركات، الزيارات، الفيدباك، السداد، التسكين... إلخ).
  2. يضيف عناصر تحليل بحرية كاملة: **دائري / أعمدة / جدول / رقم إجمالي**، مع اختيار "التقسيم حسب" أي حقل، بما في ذلك **التقسيم حسب الفريق** تلقائيًا لأي حقل مرتبط بموظف (زي "المندوب اللي عمل الزيارة" أو "المسؤول") — فبيتحول فورًا لمقارنة أداء الفرق زي في المثال.
  3. المعدل (Metric) يقدر يكون عدد السجلات أو مجموع أي حقل رقمي (زي المبلغ المتأخر أو الراتب).
  4. فلاتر تلقائية أعلى اللوحة (زي فلاتر "فريق الزيارة" و"اسم الشركة" في المثال) بتتولّد من حقول مصدر البيانات نفسه.
- لتفعيل الميزتين دول مع Supabase، لازم تشغّل `database/schema.sql` المحدّث (فيه جداول `teams` و`dashboards` و`widgets` وعمود `team` جديد في `employees`) — لو عندك قاعدة بيانات شغالة بالفعل، يكفي تنسخ الجزء الجديد بس (تحت تعليق "الفرق" في الملف) وتشغّله في SQL Editor.

## ⚠️ ملاحظات أمان مهمة قبل الاستخدام الفعلي

هذا النموذج مُعد للتجربة وعرض الفكرة، وفيه اختصارات أمنية لازم تتعالج قبل ما موظفين حقيقيين يستخدموه ببيانات حقيقية:

1. **كلمات المرور** متخزنة كنص عادي (Plain Text) في جدول `users` — لازم تتشفّر (مثلاً عبر Supabase Auth بدل الجدول اليدوي).
2. **صلاحيات قاعدة البيانات (RLS)** في `schema.sql` مفتوحة بسياسة `allow all` لكل الجداول لغرض التجربة السريعة، وده معناه إن أي حد شايف كود الصفحة (ومعاه الـ anon key) يقدر يقرا/يعدّل كل البيانات. قبل الإطلاق الفعلي لازم تُضبط سياسات RLS بحيث كل دور يشوف/يعدّل بس الجداول الخاصة بيه.
3. الـ `anon key` نفسه ظاهر في كود `index.html` لأنه بيشتغل من المتصفح مباشرة — ده طبيعي في تطبيقات Supabase العميل-مباشر، لكنه يعتمد بالكامل على إحكام سياسات RLS المذكورة فوق لحماية البيانات.
